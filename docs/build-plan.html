Daybook build plan

Daybook is a Notion-style daily note app that works offline, syncs across your devices, and installs on desktop and phone. Revision 2 replaces Supabase and Postgres with one Rust binary and one SQLite file.

What changed and why

AreaBeforeNow
BackendSupabase (hosted Postgres, Auth, Storage)One Rust binary (axum) that serves the API and the web app
DatabasePostgres with row-level securityOne SQLite file in WAL mode, every query filtered by owner
HostingCloudflare Pages plus Supabase, two servicesOne small container with one disk volume
LoginMagic link by emailEmail and password (argon2), invites created by a command line tool. No email service
Sync APITable REST calls plus a client sync loopOne endpoint, POST /api/sync, push and pull in a single round trip
Sync cursorDevice clock updated_atServer counter seq, so clock skew cannot break ordering
ImagesSupabase Storage bucket and signed URLsFiles on the volume named by their SHA-256, served by the same binary
SearchWorker index in the browserSQLite FTS5 on the server, plus a title filter that works offline
BackupSupabase backupsLitestream streams the SQLite file to object storage
Databases viewTable, board, calendarTable first. Board and calendar only if you still want them later
Desktop wrapperTauri laterDropped from the plan. The installed web app covers desktop

Rust will not make this app feel faster by itself. Typing and rendering happen in the browser, and a notes sync is a few kilobytes. The real speed comes from local-first storage, so every edit lands in IndexedDB instantly and sync runs behind it. Rust still fits well here because it ships as one small static binary with low memory use.

Decisions

TopicDecisionConsequence

BackendRust, axum, rusqliteSingle binary, embeds the built web app with rust-embed
SyncLast write wins per pagePages are the sync unit, no CRDT. Overwritten versions go to history
UsersYou plus a few invited peoplePublic sign-up does not exist. daybook invite name@example.com creates an account
HostingFree subdomainA fly.dev subdomain on a Fly.io app with a small volume. Check current free allowance before deploy
Old notesStart freshNo importer. The prototype is discarded
FeaturesRich text, drag to reorder, databases, images and filesPhases 2, 6 and 7

Cloudflare Pages no longer fits, because SQLite needs a persistent disk and the server must run all the time. A free fly.dev name replaces it. A home machine behind a Cloudflare Tunnel is the other option.

Phases

P1

Rust server skeleton

  • Cargo project with axum, rusqlite (bundled SQLite), tokio, serde, tracing.
  • One connection for writes and a small pool for reads, WAL mode, busy_timeout set. Migrations as numbered SQL files run at start.
  • Config from environment: data directory, port, session secret.
  • Serves a placeholder page and GET /health.
Done when: cargo run serves a page and creates the database file
P2

Web app and editor

  • Vite, React and TypeScript project in web/. The dev server proxies /api to the Rust server.
  • Local database in IndexedDB through Dexie.
  • TipTap with StarterKit, task list, links, slash menu and a drag handle on every block. Documents stored as TipTap JSON.
Done when: every prototype block works, plus formatting and drag, and notes survive a reload
P3

Pages and daily notes

  • Nested page tree with drag to reorder and move. Order is a fractional index string, so a move touches one row.
  • Today button, previous and next day, template for new daily notes.
  • Title filter over the local pages. Full-text search arrives with sync.
  • Trash with restore.
Done when: prototype parity reached, then delete the prototype
P4

Accounts and sync

  • daybook invite <email> prints a one-time set-password link. There is no sign-up page.
  • Login with argon2 password check, then an HttpOnly, Secure, SameSite cookie holding a random session id stored in SQLite.
  • POST /api/sync takes { cursor, changes[] }. In one transaction the server applies each change, assigns it the next seq, then returns every row with seq above the cursor.
  • Conflict rule: the change that arrives last wins. The version it replaces is copied to page_history.
  • Client keeps a dirty flag per local row. Sync runs on start, on reconnect, on focus, and a moment after typing stops.
  • FTS5 index updated in the same transaction. GET /api/search exposes it.
Done when: edit offline on two devices, reconnect, both converge, and a second account sees nothing of the first
P5

Installable app and mobile layout

  • vite-plugin-pwa: manifest, icons, service worker that caches the app shell.
  • Sidebar becomes a drawer under 700px. Touch-sized controls. Safe-area padding.
  • Offline indicator and a version check that reloads when a new build is available.
Done when: installs on a phone, opens and edits in airplane mode
P6

Images and files

  • Paste, drop, or pick an image. Resize to a maximum edge before storing.
  • Blob goes to IndexedDB first, then PUT /files/:sha256 when online. The server writes it to the volume and refuses a hash mismatch.
  • Same hash, same file, so duplicates cost nothing. A size cap protects the disk.
Done when: an image added offline shows on the other device after sync
P7

Databases

  • A database is a page whose rows are pages. Properties: text, number, select, date, checkbox.
  • Table view with sort, filter and inline edit. Rows sync as pages, so the server needs no new endpoint.
  • Board and calendar views stay optional.
Done when: a task database works as a table with filters
P8

Release

  • Multi-stage Dockerfile: build the web app, build Rust with the web app embedded, copy one binary into a small image.
  • Fly.io app with one volume at /data. Litestream replicates the database to object storage.
  • Markdown and JSON export from the app.
  • Tests: Rust integration tests for sync and ownership, Playwright for editor and offline flows.
Done when: an invited friend signs in on the live URL and cannot read your notes

Data model

create table users (
  id            integer primary key,
  email         text not null unique,
  password_hash text,                 -- null until the invite link is used
  invite_token  text,
  created_at    integer not null
);
create table sessions (
  id text primary key, user_id integer not null references users(id), expires_at integer not null
);

create table pages (
  id          text primary key,        -- uuid made on the client
  owner_id    integer not null references users(id),
  parent_id   text,
  title       text not null default '',
  kind        text not null default 'page',  -- 'page' | 'database'
  position    text not null,                 -- fractional index
  content     text,                          -- TipTap JSON
  props       text,                          -- database row values, JSON
  schema      text,                          -- database columns, JSON
  daily_date  text,                          -- 'YYYY-MM-DD' for daily notes
  deleted_at  integer,
  seq         integer not null               -- server counter, the sync cursor
);
create index pages_owner_seq on pages (owner_id, seq);
create unique index pages_daily on pages (owner_id, daily_date) where daily_date is not null;

create table page_history (page_id text, seq integer, title text, content text);
create virtual table page_fts using fts5(title, body, content='', tokenize='porter');

The single SQLite writer makes seq = max(seq) + 1 safe inside a transaction. The unique daily index stops two offline devices from leaving two notes for the same day. On sync the later one merges into the earlier one.

Risks

Same page edited on two offline devices. The last push to arrive wins and the other version sits in history. If it happens often, give that page type a Yjs document later.

The server is now yours to keep running. Supabase handled backups, patches and uptime. Litestream and a pinned container image cover the basics, and a restore test belongs in phase 8.

One writer. SQLite allows one write at a time. For a handful of users this is far below any limit. It only matters at hundreds of active writers.

Password login replaces magic links. Add a rate limit on login and a reset command in the command line tool, because there is no email service to recover an account.

Service worker caching. A stale app shell can run against a newer schema. Version the local database and reload when the worker updates.

Databases are the largest item. Ship the table view alone first.

Open items

Fly.io's free allowance changes over time. Confirm the current terms before phase 8. If it no longer fits, a home machine with a Cloudflare Tunnel keeps the same single-binary design.
